# 분석 보고서: 왜 고객은 엑셀을 떠나지 못하는가

> **목적**: 배합/R&D 데이터 관리 제품이 엑셀을 상대로 20년간 패배해 온 역사를 분석하고, 자사 제품 설계 시 반복하지 말아야 할 패턴을 정리한다.
>
> **대상 독자**: 제품 기획·세일즈·엔지니어링 의사결정자
>
> **작성 맥락**: 다쏘시스템 BIOVIA 컨설팅 사업을 영위하는 자사가 자체 SW 제품(배합 R&D + AI 플랫폼)을 기획하는 단계에서, 시장 진입 전 검증해야 할 핵심 가설 중 하나에 대한 사전 분석 자료.

---

## Executive Summary

1. **엑셀은 "허술한 DB"가 아니라 "무료 프로그래밍 환경"이다.** 12개의 구조적 강점을 갖고 있으며, 이를 과소평가한 ELN/LIMS 제품들이 20년간 반복적으로 실패해 왔다.
2. **ELN/LIMS 실패에는 7가지 반복 패턴**이 있다: 기능 패리티 함정, IT 주도 롤아웃, 관리자 설정 과다, 스키마 근본주의, 마이그레이션 마비, 리포팅 단절, 통합 블랙홀.
3. **엑셀을 부분적으로 이긴 제품들의 공통점**은 엑셀과 정면 대결하지 않고, 단일 킬러 워크플로우를 명확히 소유하며, 사용자 셀프 서비스와 완벽한 상호운용성을 갖췄다는 점이다.
4. **자사 제품의 권장 포지셔닝**은 "엑셀 대체"가 아니라 **"엑셀 데이터를 AI가 쓸 수 있게 정제하는 레이어"**이며, IT 승인이 불필요한 연구팀장 직접 결정 조직을 초기 타겟으로 삼아야 한다.
5. **고객 인터뷰 단계에서 활용 가능한 레드 플래그/긍정 신호 사전**을 부록으로 첨부한다.

## Part 1: 엑셀의 12가지 구조적 강점

경쟁사가 아닌 **엑셀 자체를 진지한 경쟁 제품으로 해부**해야 한다. 대부분의 ELN/LIMS는 이 분석을 생략하고 시작했다가 실패했다.

| # | 엑셀의 강점 | 대체 제품이 놓치는 것 |
|---|---|---|
| 1 | **제로 마찰 입력**: 클릭 → 타이핑 → 끝 | ELN: 로그인 → 프로젝트 선택 → 실험 생성 → 폼 작성 → 저장 (5~10배 느림) |
| 2 | **스키마 자유도**: 오늘 컬럼 3개, 내일 5개 | 대부분 제품은 관리자가 스키마를 미리 정의해야 함 |
| 3 | **무한 계산 엔진**: 셀에 바로 수식 | ELN은 수식 비활성화되거나 별도 "계산 필드"로 제한됨 |
| 4 | **오프라인/이동성**: 비행기에서도 작동 | SaaS는 네트워크 필수 |
| 5 | **상호운용성**: 누구에게나 메일로 공유 가능 | 제품 내부 데이터는 사실상 잠김 |
| 6 | **한계비용 제로**: 이미 MS365에 포함됨 | 사용자당 연 수십~수백만원 |
| 7 | **학습곡선 제로**: 신입도 당일 사용 | ELN은 반나절~1주 교육 + 매뉴얼 |
| 8 | **사용자 자체 커스터마이징**: 피벗·매크로·조건부 서식 | 관리자/IT/컨설턴트 필요 |
| 9 | **시각적 자유도**: 셀 색칠·메모·도형으로 "암묵지" 표현 | 구조화 폼은 맥락 전달 불가 |
| 10 | **벤더 락인 공포 없음**: 파일은 내 PC에 있음 | SaaS 탈퇴 시 데이터 뽑기 고통 |
| 11 | **파워유저의 자존심**: 20년 내공 = 정체성 | "당신의 전문성을 대체" = 적대감 유발 |
| 12 | **숨겨진 초능력**: 팀별 매크로·템플릿·관습 | 외부 설계자는 그 존재 자체를 모름 |

**핵심 통찰**: 엑셀은 무한 유연성을 가진 무료 프로그래밍 환경이다. 이 본질을 받아들이지 않으면 어떤 제품을 만들어도 진다.

## Part 2: ELN/LIMS 20년 실패사

### 케이스 1: CambridgeSoft E-Notebook (2000년대 초~)

- **상황**: 화학 업계 ELN 표준이 되려 함. PerkinElmer가 인수.
- **결과**: 제약 R&D에서 일부 성공했으나 **소재/배합 영역은 거의 침투 못 함**. 현재는 레거시 제품.
- **교훈**: "화학 구조만 잘 다루면 R&D 전체가 따라온다"는 가정이 틀림. 구조 중심 UX는 배합 현장과 불일치.

### 케이스 2: IDBS E-WorkBook (현 Revvity)

- **상황**: 대형 제약사 중심 10년 이상 영업. 기능 풍부.
- **결과**: **중견기업 시장 진입 실패**. 라이선스 + 구축비 과다, 도입 18개월+.
- **교훈**: "다운마켓 이동" 불가능 구조. 대기업 최적화 제품은 중견으로 못 내려옴.

### 케이스 3: Benchling (바이오 성공 / 화학·소재 실패)

- **상황**: 바이오 스타트업에서 폭발적 성장. 클로닝·플라스미드 워크플로우에서 엑셀+SnapGene을 실제 대체.
- **결과**: **화학/소재 영역 진출은 부진**. "Benchling for Chemicals" 시도 확산 실패.
- **교훈**: 단일 킬러 워크플로우(DNA 시퀀스 편집)가 명확했기에 바이오는 이김. 범용 확장은 진다.

### 케이스 4: BIOVIA Workbook / CISPro

- **상황**: Dassault가 기업 R&D 디지털화 대표 주자로 포지셔닝.
- **결과**: 대형사 도입은 됐으나 **실제 사용은 부분적**. 실무 연구원은 엑셀로 1차 작업 → Workbook에 "공식 기록"만 옮기는 이중 입력 발생.
- **교훈**: 공식 시스템과 실제 작업 도구의 분리가 본질적 실패. 비싼 제품을 샀으나 엑셀은 그대로.

### 케이스 5: 한국 대기업 자체 구축 ELN (2010년대)

- **상황**: 삼성·LG·SK 계열 SI 통한 자체 구축. 수십억 투입.
- **결과**: 상당수가 **5년 내 사용률 20% 미만**으로 전락. 일부 공식 폐기. 연구원은 엑셀 + 공용 폴더로 회귀.
- **교훈**: 강제 도입 + IT 주도 구축은 장기적으로 반드시 실패. 연구원의 자발적 선택을 받지 못한 시스템은 죽는다.

### 케이스 6: LabWare LIMS / Thermo SampleManager

- **상황**: QC 랩에서 성공. 샘플 바코드, 기기 연동.
- **결과**: **R&D/배합 영역 확장 실패**. QC=루틴·반복·규제, R&D=탐색·일회성·자유도. 카테고리가 다름.
- **교훈**: QC 사고방식 제품을 R&D에 팔면 안 됨.

## Part 3: 실패 패턴 7가지 (반복 금지 목록)

| # | 패턴명 | 증상 | 결과 | 대표 피해자 |
|---|---|---|---|---|
| 1 | **기능 패리티 함정** | "엑셀이 되는 건 다 되고 + α" | 무거워지고 엑셀 속도 우위를 못 깸 | 초기 ELN의 스프레드시트 뷰 |
| 2 | **IT 주도 롤아웃** | CIO/품질팀이 도입 결정, 연구팀 통보받음 | 수동적 저항 → 이중 입력 → 유명무실 | 한국 대기업 자체 구축 ELN |
| 3 | **관리자 설정 과다** | 템플릿/워크플로우/권한을 관리자가 정의 | IT 프로젝트화 → 6개월 구축 → 요구사항 변함 | BIOVIA Workbook 전형적 배포 |
| 4 | **스키마 근본주의** | "배합은 이렇게 입력해야 합니다" | 현장 다양성(phr·wt%·mol%·부)과 불일치 → 반발 | STARLIMS 배합 모듈 |
| 5 | **마이그레이션 마비** | "쓰려면 과거 10년 데이터 다 넣어야 해요" | 1~2년 프로젝트 → 동력 상실 → 반쯤 채워진 DB | 다수 LIMS 구축 현장 |
| 6 | **리포팅 단절** | 내부 데이터는 보기 좋으나 보고서 추출 어려움 | 제품 → 엑셀 → PPT 재추출 → "처음부터 엑셀" | 초기 클라우드 ELN |
| 7 | **통합 블랙홀** | 기기/ERP/PPT/Outlook 어디와도 연결 안 됨 | 입력은 되지만 출구 없음 → 고립감 | 초기 Benchling의 화학 접근 |

## Part 4: 엑셀을 부분적으로 이긴 제품들의 승리 패턴

### Win 1: "스프레드시트 느낌" 유지 (Airtable/Smartsheet 모델)
사용자는 셀을 편집하는 것처럼 느끼되, 뒤에서는 구조화된 DB. **속도 마찰 제로화**.

### Win 2: 마이그레이션 대신 임포트 (Paste, Don't Migrate)
엑셀 붙여넣기 → 자동 파싱 → 구조화. "엑셀 버리지 마세요. 그냥 붙여넣어 주세요."

### Win 3: 단일 킬러 워크플로우 (Do ONE Thing Better)
Benchling = DNA 편집. Figma = 협업 디자인. 자사의 경우 후보는 **"분자 구조 descriptor 자동 계산 + 물성 예측"**.

### Win 4: 사용자 셀프 서비스 스키마 (Notion/Airtable식)
관리자/IT 없이 팀장이 스키마 수정 가능. 연구팀 자율 운영.

### Win 5: 상호운용, 락인 아님 (Interop, Not Lock-in)
언제든 엑셀로 내보내기·가져오기 완벽. 엑셀이 경쟁자가 아니라 연동 파트너가 됨.

### Win 6: 풀(Pull) 전략 — 엑셀이 줄 수 없는 것만 주기
- 화학 구조 기반 descriptor
- 팀간 실시간 협업·댓글
- 다른 배합과의 유사도 검색
- AI 예측
- 기기 데이터 자동 수집

→ 엑셀에서 절대 불가능한 기능만 강조한다.

## Part 5: 자사 제품 설계에 주는 7가지 원칙

매 기능 의사결정 시 이 체크리스트를 적용한다.

### 원칙 1: 엑셀을 적이 아닌 동반자로 취급하라
- 제품 첫 화면 CTA: **"엑셀 붙여넣기로 시작"**
- 마케팅 메시지에서 "엑셀 대체" 단어 사용 금지
- 대신: **"엑셀 데이터를 AI가 쓸 수 있게 만들어 드립니다"**

### 원칙 2: 마이그레이션 프로젝트를 만들지 마라
- "전사 데이터 이관" 제안 금지
- "파일 1개 업로드 → 5분 내 가치 체험" 온보딩
- 3년치 엑셀이 있어야 가치가 나오는 구조면 실패

### 원칙 3: 단일 킬러 워크플로우를 먼저 완성하라
- 후보: **"SMILES/CAS 입력 → 자동 descriptor + 유사 배합 검색 + 물성 예측"**
- "엑셀로는 절대 못 한다"로 각인
- 두 번째 워크플로우는 첫 번째 검증 후 추가

### 원칙 4: IT가 아닌 연구팀장에게 팔아라
- 가격 3,000만원/년 이하 (부서장 전결 범위)
- 자체 설정 가능한 스키마 (IT 컨설팅 불필요)
- 14일 무료 트라이얼 + 1시간 내 첫 가치 체험

### 원칙 5: 입력 마찰을 엑셀 수준으로 낮춰라
- 탭/방향키 네비게이션
- Excel-like 셀 편집 UX
- 엑셀 붙여넣기·드래그 기본 지원
- 입력 시 클릭 3회 이내 목표

### 원칙 6: 내보내기를 완벽히 하라
- 엑셀·PPT·PDF 보고서 원클릭
- 엑셀 re-import 라운드트립
- "언제든 빠져나갈 수 있다"는 신뢰 형성

### 원칙 7: 강제 도입 냄새가 나는 고객은 피하라
- IT/QA 주도 도입 검토는 초기 단계 거절
- 연구팀장이 직접 결정하는 조직만 초기 고객 선별
- 초기 파일럿 실패의 95%는 강제 도입 문화에서 발생

## 부록 A: 고객 인터뷰 레드 플래그/긍정 신호 사전

### 레드 플래그 (초기 파일럿 대상 제외)

| 고객의 말 | 의미 | 대응 |
|---|---|---|
| "IT 검토 먼저 받아야 해요" | 도입 6개월+ 예약 | 초기 대상 제외 |
| "우리 데이터를 다 이관해주시나요?" | 마이그레이션 함정 | 제외 또는 명시적 거절 |
| "엑셀의 ○○ 기능도 다 되나요?" | 기능 패리티 함정 진입 | "그건 엑셀이 계속 잘하는 영역입니다" |
| "연구원들이 써야 하는데 안 써요" | 강제 도입 문화 | 연구팀장 직접 결정 조직으로 대체 |
| "전사 표준으로 삼으려고요" | 톱다운 프로젝트화 | 한 팀 파일럿만 받겠다고 제한 |
| "우리는 GMP/Part 11 규제 대상이에요" | 엔터프라이즈 기능 요구 폭증 | 비규제 소재/CPG 영역 고객 선별 |

### 긍정 신호 (우선 파일럿 대상)

| 고객의 말 | 의미 |
|---|---|
| "엑셀 다 뒤지는 데 주당 ○시간 쓰고 있어요" | 정량화된 pain |
| "○○ 연구원이 퇴사할 때 데이터 다 잃어버렸어요" | 구체적 손실 경험 |
| "예전에 ○○ 툴 써봤는데 이래서 안 됐어요" | 학습된 고객 (과거 시도 경험) |
| "다음 달에 파일럿 시작할 수 있어요?" | 짧은 리드타임 = 진짜 니즈 |

## 부록 B: 검증되지 않은 가정 목록 (인터뷰로 검증 필요)

본 보고서가 전제로 깐 가설들. 시장조사로 반드시 검증해야 한다.

- [ ] 한국 중견 소재기업의 R&D 데이터는 실제로 엑셀에 흩어져 있다
- [ ] 그 흩어짐이 측정 가능한 손실(시간/비용/이직 시 지식 유실)을 발생시킨다
- [ ] 그 손실을 해결하기 위해 연 1,000만~3,000만원 지불 의향이 있다
- [ ] 연구팀장 전결로 그 금액이 결재 가능하다
- [ ] 도입 후 운영을 위한 데이터 입력 인력/시간이 확보 가능하다
